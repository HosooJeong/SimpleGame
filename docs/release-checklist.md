# 스낵게임 — 출시·수익화 절차 체크리스트

## 1. Google Play 개발자 계정 [유저]

- https://play.google.com/console 에서 **개인 계정** 가입
- **비용: $25 (1회, 카드 결제)** — 이 프로젝트의 유일한 필수 지출
- 신원 확인: 신분증 + 주소 증빙, 이메일·전화 인증
- ⚠️ **신규 개인 계정은 프로덕션 출시 전 비공개 테스트 의무**: 일정 인원(과거 20명 → 최근 12명으로 완화, 콘솔 표시 기준 확인)의 테스터가 **14일간** 연속 옵트인 상태여야 프로덕션 접근 신청 가능. 지인 동원 필요.

## 2. 수익 수취 준비 [유저]

- Play Console에서 **결제 프로필(머천트)** 개설 — IAP(광고 제거) 판매에 필수, 무료
- 지급 계좌(본인 은행) + 세금 정보(개인, 미국 세금 양식 포함) 등록
- 구글 수수료: IAP 매출의 15% (연 $100만 이하 구간) / 광고 수익은 AdMob에서 별도 정산
- 참고: 수익 발생 시 종합소득세 신고 대상. 규모 커지면 사업자 등록 검토.

## 3. GPGS(랭킹) 콘솔 설정 [유저 — 가이드는 Claude 제공] · 비용 0원

1. Play Console → "Play 게임즈 서비스" → 프로젝트 생성 (Google Cloud 프로젝트 자동 연결, 무료)
2. OAuth 동의 화면 구성 + 사용자 인증 정보에 **앱 서명 SHA-1** 등록 (키스토어 만든 뒤)
3. **리더보드 14개 생성** — 게임별 점수 형식·정렬·한계값(부정 기록 자동 차단):

| 게임 | 정렬 | 형식 | 한계값 (min~max) 추천 |
|------|------|------|----------------------|
| 반응속도 | 낮을수록 좋음 | 밀리초 | 120 ~ 2,000 ms |
| 숫자 순서 | 낮을수록 좋음 | 밀리초 | 5,000 ~ 300,000 ms |
| 탭 스피드 | 높을수록 좋음 | 숫자 | 1 ~ 200 회 |
| 타이밍 스톱 | 높을수록 좋음 | 숫자 | 0 ~ 500 점 |
| 순서 기억 | 높을수록 좋음 | 숫자 | 1 ~ 50 단계 |
| 정확한 10초 | 낮을수록 좋음 | 밀리초 | 0 ~ 10,000 ms |
| 다른 색 찾기 | 높을수록 좋음 | 숫자 | 1 ~ 60 단계 |
| 색깔 함정 | 높을수록 좋음 | 숫자 | 0 ~ 60 점 |
| 순간 기억 | 높을수록 좋음 | 숫자 | 3 ~ 20 개 |
| 반반 자르기 | 높을수록 좋음 | 숫자 | 0 ~ 500 점 |
| 완벽한 원 | 높을수록 좋음 | 숫자 (×10 정수 제출: 90.4% → 904) | 0 ~ 1,000 |
| 셔플 추적 | 높을수록 좋음 | 숫자 | 0 ~ 30 단계 |
| 순간 셈 | 높을수록 좋음 | 숫자 | 0 ~ 15 단계 |
| 가짜 신호 | 높을수록 좋음 | 숫자 | 0 ~ 200 개 |

> 완벽한 원은 로컬 기록이 소수점 1자리(%)라 GPGS 정수 제약에 맞춰 ×10 해서 제출·표시 변환 필요 (v2 구현 시 반영).

4. 테스터 등록 → 게임 서비스 게시
5. **부정 사용자 제재**: 이상 기록 발견 시 Play Games Management API의 플레이어 숨김(hide/unhide)으로 리더보드에서 제외 — [Claude]가 제재용 스크립트 작성 가능

### 3-1. 부정행위 대응 전략 (2026-08-21 확정)

> 전제: 완전 오프라인 + 클라이언트 점수 제출 구조에서 100% 차단은 불가능. 목표는 "차단"이 아니라 **랭킹 신뢰도 유지** — 캐주얼 치터의 비용을 올리고, 뚫린 기록이 보드를 오래 오염시키지 못하게 한다.

게임별 취약점: 매크로(탭 스피드·반응속도·정확한 10초·타이밍 스톱, 위협도 높음) / 녹화 후 입력(순서 기억·순간 기억, 중간) / 화면 인식 봇(다른 색·색깔 함정·반반, 낮음) / 메모리 조작·루팅(전부).

비용 대비 효과 순 4겹 방어:

1. **GPGS 한계값** (위 표) — 물리적으로 불가능한 값은 제출 단계에서 자동 거부. 콘솔 설정만으로 완료.
2. **주간 리더보드를 명예의전당 기본 화면으로** — GPGS 기본 제공(일간/주간/전체). 조작 기록이 매주 자동 정화되고, 유지 비용이 치터 쪽으로 넘어감. 가장 싸고 효과 큰 방어.
3. **랭킹 도전 중 `FLAG_SECURE`** — 기기 내 스크린샷·녹화를 OS 수준 차단(랭킹 도전 플레이 중에만 동적 적용, 일반 공유 스크린샷은 방해 안 함). 기억류 게임에는 **입력 제한시간**(다음 입력까지 2~3초)을 더해 타기기 촬영도 귀찮게 만든다.
4. **입력 패턴 검사 + 수동 제재** — 탭 간격이 ms 단위로 균일하거나 반응속도 5라운드가 전부 동일하면 매크로. 걸리면 조용히 랭킹 제출 생략(연습 기록으로만 저장). 그래도 올라온 기록은 Management API 숨김으로 제재.

UI 프레이밍: "전체 1등"보다 **상위 N% + 순위**를 함께 노출 — 치터가 망칠 수 있는 건 1등 자리 하나뿐이게 만든다.

### 3-2. 주간 달성 아카이브 (로컬 업적 시스템, 2026-08-21 확정)

주간 보드의 약점("기록이 매주 증발")을 로컬 아카이브로 보완 — 순위는 매주 리셋돼도 성취는 영구 소장.

- **스냅샷 방식**: GPGS는 리셋된 지난주 순위를 다시 조회해주지 않음 → 랭킹 도전 **제출 직후마다** 내 순위/상위 %를 조회해 그 주의 **최고 도달치**를 갱신, 주가 넘어가면 아카이브에 확정 기록. 문구는 "주간 최종 순위"가 아닌 **"달성 기록"**(그 주에 상위 N%까지 도달)으로 정직하게.
- **저장**: shared_preferences 스키마 확장 (주차 × 게임 × 최고 상위 % / 순위 / 점수). 백엔드 불필요.
- **v2 첫 버전 범위**: 아카이브 목록 화면 하나로 최소하게. 마일스톤 뱃지(첫 상위 10% 등)는 반응 보고 추가.
- 효과: 주간 수집 습관(리텐션) → 도전권 소모 → 광고 시청 루프. 유저 자부심이 개인 컬렉션에 쌓여 부정행위 내성도 높아짐.

## 4. AdMob(광고) 설정 [유저 — 가이드는 Claude 제공] · 가입 무료

1. https://admob.google.com 가입 (같은 구글 계정 권장)
2. 앱 등록 → **앱 ID** 발급, **보상형 광고 단위** 생성 → ID들을 Claude에게 전달
3. **app-ads.txt**: 스토어 등록정보의 "개발자 웹사이트" 도메인에 파일 호스팅 필요 → GitHub Pages로 무료 해결 [Claude 세팅 가능]
4. 지급 정보(계좌) 등록 — 수익 $100 도달 시 지급
5. EU 배포 시 UMP 동의 폼 설정 (구글 무료 도구)
